**本轮只落两个写接口，但 B1 要列出全部 7 个动作。** 目的不是现在全写完，而是让两人看见"一共有多少口子"，互审时能明确指出缺口——写在上面 `x-next-batch` 里了。

### 一处必须说明的边界

`POST /exams/{examId}/plan-previews` 返回的是 `202 + job_id`，不是排好的计划。

意思是：**前端提交后要轮询 `GET /jobs/{jobId}`**，直到状态变成 `needs_review` 或 `done` 才能拿预览结果。不能指望一个请求挂在原地等两分钟。

## B3 统一错误格式

所有失败响应长得一样，只有一层 `error`：

```json
{
  "error": {
    "code": "VERSION_CONFLICT",
    "message": "范围草稿已有更新，请查看差异后重试",
    "details": { "current_version": 3, "your_version": 2 },
    "request_id": "req_02"
  }
}
```

四个字段各有分工，缺一个前端就会难做：

| 字段 | 给谁看 | 作用 |
| --- | --- | --- |
| `code` | 程序 | 前端据此决定走哪段处理逻辑，不要靠匹配 message 文字 |
| `message` | 用户 | 直接显示在界面上，必须是中文人话，不能是堆栈信息 |
| `details` | 程序 | 结构化补充，比如字段名、当前版本号、非法 ID 列表 |
| `request_id` | 查问题 | 用户报"出错了"时，凭这个号在后端日志里找到那一次请求 |

### 四类场景，分别怎么处理

| 场景 | HTTP | `code` | 前端该做什么 | 数据怎么保 |
| --- | --- | --- | --- | --- |
| **输入不合法**（课程名为空、日期早于今天） | 400 | `VALIDATION_ERROR` | 定位到具体输入框标红，`details.field` 告诉你哪一个 | 用户已填的其它内容全部保留，不清空表单 |
| **资源不存在**（考试被删了还在操作） | 404 | `VALIDATION_ERROR` | 提示"这场考试已不存在"，给一个回列表的按钮 | 不清空当前页面，让用户能复制走已填内容 |
| **连点两次**（手抖点了两下创建） | 200 / 201 | 无错误 | **不报错**，正常返回第一次的结果 | 靠 `Idempotency-Key` 挡住，第二次直接返回第一次的产物 |
| **两人同时改**（伙伴在另一台改了同样的范围） | 409 | `VERSION_CONFLICT` | 弹窗展示"你的版本 / 服务器版本"差异，让用户选保留哪份 | 绝不静默覆盖，用户没选之前两边都不动 |

### 连点两次 vs 同时修改，别搞混

这两个都是"撞车"，但处理方式完全相反：

- **连点**：是**同一个人**的手误，应该**假装无事发生**——返回第一次的结果，用户看到的是一次成功
- **同时改**：是**两个人**的意见不同，必须**打断并让人决定**——不能替用户选

判据也简单：连点靠 `Idempotency-Key`（同一个键 = 同一次意图）；同时改靠 `expected_version`（版本号对不上 = 别人动过了）。

## B4 预览与应用是否分离 —— 检查结论

**结论：是分开的，两条独立接口。** 依据设计文档 API-07 与 API-08。

| 环节 | 接口 | 是否写正式计划 | 关键约束 |
| --- | --- | --- | --- |
| 生成预览 | `POST /exams/{examId}/plan-previews` | ❌ 不写 | 只产出 `preview_id` 与差异清单，异步任务 |
| 应用预览 | `POST /plans/{planId}/applications` | ✅ 写新版本 | 必须带 `preview_id` + `expected_version`，后端重新校验全部约束 |

**为什么必须分开**：预览可能算出你不满意的结果（比如把重点往后挪了），也可能算出排不下的情况。如果预览直接改正式计划，一次误操作就毁了用户辛苦排的计划，而且没法撤销。分开之后，取消预览只删草稿，正式计划毫发无伤。

**应用时必须重验**，因为预览和应用之间可能隔了几分钟，用户可能已经完成了某个任务、或者又标了一天不可学。后端不能盲信预览结果，要重新检查：考试日、不可学日容量、已锁定任务、已完成任务、前置依赖。

## 互审时请伙伴重点看这几处

1. `scope-draft` 是**覆盖式**保存（PUT 整份快照），不是增量补丁——你的示例数据要能整份填进去
2. `expected_version` 从 0 开始，第一次保存后后端返回 1，下次要传 1
3. 所有日期是 `YYYY-MM-DD` 字符串，不是时间戳
4. `priority` 只有 `normal` 和 `key` 两个值，和术语表一致
5. 返回结构统一包 `data` + `meta`，错误统一包 `error`——前端只写一次解析逻辑
