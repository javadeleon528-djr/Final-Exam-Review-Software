# T02 工程骨架与本机联通：三方任务分工

状态：进行中（同学 B 先开始数据库连接）｜模式：学习优先｜范围：T02，不提前实现 T03 的课程业务。

## 目标与完成标准

在一台新电脑上，按照 README 安装依赖、执行数据库迁移、启动后端与前端。打开浏览器能看到前端页面；页面请求真实的 `GET /api/v1/health`，显示服务和数据库状态。重启两端后仍可运行。

**分工原则：两位同学学习并负责后端基础设施与集成；Codex 负责前端代码。** 前端验收由同学按页面行为完成，不要求两位同学学习 React、TypeScript 或 CSS。

## 共同约定（开工前 15 分钟）

- 正式代码放在项目根目录的 `backend/` 与 `frontend/`；现有单文件 HTML 保留作为 UI 参考。
- 后端开发地址为 `http://127.0.0.1:8000`，前端开发地址暂定为 `http://127.0.0.1:5173`。API 路径统一以 `/api/v1` 开头。
- 健康检查成功响应：`{"data":{"status":"ok","database":"ok"},"meta":{"request_id":"..."}}`；数据库不可用时返回 503，前端显示明确提示。
- 数据库存储位置由后端配置决定，默认放在项目内的本地数据目录；数据库文件不得提交到 Git。
- 先各自在自己的分支工作，合并顺序：后端应用入口 → 数据库模块 → 前端；接口字段改变时先更新 `docs/api-contract.yaml`。
- 2026-11-08 用户决定将 T01 视为已审查并直接进入 T02；两人继续使用 `docs/api-contract.yaml` 中相同的字段约定。T01 文档的 Git 提交状态单独处理。

## 同学 A：后端应用与启动

**负责文件：** `backend/pyproject.toml`、`backend/app/main.py`、`backend/app/api/health.py`、`backend/README.md`。数据库目录与迁移文件由同学 B 负责。

1. **20–30 分钟：搭最小 FastAPI 应用。** 创建应用入口，运行后能打开 `/docs`。先写一个不访问数据库的 `/api/v1/health`，返回约定的 `data` 与 `meta`。
2. **20–30 分钟：处理配置与启动。** 把监听地址和数据库路径放进配置，明确开发启动命令。不要把 API 密钥写进代码或提交到 Git。
3. **20–30 分钟：集成 B 的数据库检查。** B 提供数据库连接检查函数后，在健康接口调用它；数据库失败时返回 503，保留可读的错误信息。
4. **15 分钟：独立验收。** 启动后访问 `/docs` 与健康接口；故意把数据库路径指向不可用位置，确认失败能被发现。

**需要理解：** 应用入口、路由与依赖调用之间的关系；200 与 503 分别说明什么。**不做：** 课程创建接口、AI 调用、前端页面。

## 同学 B：SQLite、ORM 与迁移

**负责文件：** `backend/app/db/`、`backend/alembic/`、`backend/alembic.ini`、`backend/tests/test_db_smoke.py`。需要增加依赖时，告诉 A，由 A 统一修改 `pyproject.toml`。

1. **20–30 分钟：建立数据库连接。** 从 A 的配置接收 SQLite 地址，完成 `backend/app/db/connection.py` 中的 `make_engine(database_url)` 和 `check_database(engine)`；后者执行简单查询判断连接是否可用。A 的路由通过这个函数检查数据库。
2. **30–45 分钟：建立第一条迁移。** 用 SQLAlchemy 定义最小 `Course` 表：稳定 ID、名称、可选说明、创建时间、归档时间；用 Alembic 生成并检查迁移，执行 `upgrade head`。
3. **20–30 分钟：验证持久化与重复迁移。** 在测试数据库中插入一条课程记录，关闭连接后重新打开仍能读到；再次执行迁移不应报错或重复建表。
4. **15 分钟：向 A 交接。** 告诉 A `check_database()` 的导入路径、成功／失败行为、数据库配置项和迁移命令。

**需要理解：** 连接、模型、迁移各解决什么问题；为什么修改模型后还需要迁移。**不做：** 课程 HTTP 接口、考试范围表、前端页面。

## Codex：前端工程与联通页面

**负责文件：** `frontend/`，以及根目录 README 中的前端启动说明；不修改两位同学负责的后端业务文件。

1. 建立 React + TypeScript + Vite 工程与基本页面框架，沿用已确定的视觉方向。
2. 做一个简单的本机服务状态页，读取真实健康接口，展示“连接中／已连接／连接失败／数据库不可用”，并提供重试按钮。
3. 配置开发代理或 API 基址，不在页面中硬编码生产地址；请求失败时给出可理解的提示。
4. 运行构建与页面联通检查，交给两位同学按浏览器操作验收。课程创建和考试范围 UI 留到 T04。

两位同学只需检查页面是否准确显示后端真实状态、失败时是否可重试，无需学习组件实现。

## 接口交接与合并顺序

| 交接 | 提供方 → 接收方 | 可以开始下一步的证据 |
| --- | --- | --- |
| 健康接口格式与地址 | A → Codex | `/api/v1/health` 的实际响应与契约一致 |
| 数据库检查函数与迁移命令 | B → A | 测试数据库迁移和连接检查通过 |
| 可运行后端 | A、B → Codex | 后端启动、`/docs` 可打开、健康接口返回数据库状态 |
| 前后端联通页面 | Codex → A、B | 浏览器显示真实状态；关闭后端后显示失败，重开后重试成功 |

各自修改自己的目录；A 与 B 都会用到 `backend/pyproject.toml`，由 A 统一维护依赖，B 只提交需要增加的依赖清单。不要同时修改同一个文件。

## 最终验收（两位同学一起做，约 20 分钟）

1. 按 README 在干净环境安装后端和前端依赖，执行迁移并启动两端。
2. 打开后端 `/docs`、健康接口与前端页面，确认浏览器显示的是接口真实结果。
3. 停止后端，前端应显示连接失败；恢复后端后点击重试，应恢复正常。
4. 停止并重开程序，数据库表与测试记录仍存在；重复执行迁移不报错。
5. 运行数据库冒烟测试与前端构建，记录命令及结果。所有条件满足后才进入 T03。

**T02 不要求：** 完整课程 CRUD、知识点目录、AI 接口、资料爬取或原型里的全部界面。它只把之后开发所需的运行基础搭稳。
