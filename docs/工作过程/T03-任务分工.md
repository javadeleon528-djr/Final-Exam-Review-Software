# T03 课程、知识档案与考试范围：任务分工

状态：待开工｜模式：学习优先｜负责人：javadeleon（数据库）、萝卜头（后端接口）、Codex（契约与联调审查）。

## 目标与边界

不依赖 AI 密钥，完成“创建课程 → 建知识点 → 修改自评 → 创建考试 → 保存并确认考试范围 → 重启后仍可读取”的后端闭环。课程资料先保存来源元数据；正文提取、OCR 和抓取留给 T08。前端课程与考试范围页面属于 T04。

T03 的来源接口已在 `api-contract.yaml` 中明确为链接／笔记登记与列表读取，登记成功返回 201，不代表正文已经提取。文件上传及提取任务在 T08 接入；总技术文档 API-03 的“上传后立即返回提取任务”表述需要在后续文档同步时拆开。

`GET /exams/{exam_id}/scope` 已增加可选的 `version` 查询参数：不传读最新版，传入正整数读指定历史正式版本。萝卜头按此实现，javadeleon 保留不可变版本数据。

## 开工门槛

1. T02 的后端迁移、健康检查、持久化测试已通过；Codex 与两人还需共同完成前端真实健康状态和停止／恢复后端的浏览器验收。此项不阻止 T03 的设计与独立编码，但 T03 不以此替代 T02 验收。
2. 以 `docs/api-contract.yaml` 为接口字段依据，以 `docs/requirements-a.md` 的术语归属为数据依据。发现冲突先改契约，再写代码。
3. 单机单用户版本不做登录，但知识点属于课程、自评属于用户＋知识点、考试范围属于考试。换考试不删除课程知识点与自评。

## 第一段：课程与知识点

### javadeleon：持久化层

1. **30–45 分钟：审查表关系。** 先读 `T03-数据库设计草案.md`，核对 `courses`、`knowledge_points`、`user_point_profiles` 的主键、外键、唯一约束和删除规则；把不同意的取舍记在草案中。保留既有 `Course` 表和迁移；新字段用新迁移，不重写已执行的迁移。
2. **30–45 分钟：模型与迁移。** 知识点使用稳定 ID、课程 ID、可选父节点、名称和版本；自评与 AI 建议分列或分表，AI 不覆盖自评。父节点必须属于同一课程，循环父子关系由业务层阻止。
3. **30–45 分钟：仓储函数。** 提供创建／列出课程、创建／列出知识点、按 ID 读取及更新自评所需的数据库操作。事务由调用方控制，失败后可回滚。
4. **20–30 分钟：数据库测试。** 用临时库执行迁移，写入课程、父子知识点与自评；关闭重开后验证数据存在，重复迁移后仍存在。

**交给萝卜头：** 模型字段表、迁移版本号、仓储函数签名及异常行为。不要只口头说明。

### 萝卜头：接口层

1. **30–45 分钟：课程接口。** 完成 `GET/POST /api/v1/courses`。名称去首尾空格；空名按契约返回 400，同名按契约返回 409；创建后返回稳定 ID、时间和统一 `data/meta`。
2. **30–45 分钟：知识点接口。** 完成 `GET/POST /api/v1/courses/{course_id}/points`；课程不存在返回 404，空知识点列表正常返回 200。父节点不属于该课程时拒绝创建。
3. **20–30 分钟：自评接口。** 完成 `PUT /api/v1/points/{point_id}/self-status`，校验四态和 `expected_version`；版本不符返回 409，只改变用户自评，不覆盖 AI 建议。
4. **20–30 分钟：API 测试。** 覆盖成功、空值、重复、跨课程父节点与版本冲突。使用临时数据库，不依赖真实 `data/study.db`。

## 第二段：考试与范围版本

### javadeleon：持久化层

1. **30–45 分钟：新迁移。** 建 `exams`、范围草稿与正式范围版本／条目表。条目必须保存 `included` 和 `priority`；考试与知识点须属于同一课程。
2. **30–45 分钟：事务与版本。** 提供读取／覆盖草稿、确认草稿为正式版本、读取某个正式版本所需操作。确认时保留旧正式版本，不原地改写。
3. **20–30 分钟：数据库测试。** 两场考试共用课程知识点但范围不同；修改一场考试不影响另一场；重新确认后旧版本仍可查，自评仍在。

### 萝卜头：接口层

1. **30–45 分钟：考试接口。** 完成 `GET/POST /api/v1/courses/{course_id}/exams`，验证日期和课程归属。
2. **30–45 分钟：范围草稿。** 完成 `GET/PUT /api/v1/exams/{exam_id}/scope-draft`。按契约用 `expected_version` 防止静默覆盖；草稿可为空，条目中 `included=false` 表示本次不考。
3. **30–45 分钟：确认与读取。** 完成 `POST /api/v1/exams/{exam_id}/scope-confirmations` 和 `GET /api/v1/exams/{exam_id}/scope`。空草稿不可确认；只确认用户选定的本场考试范围；旧版本可查。
4. **20–30 分钟：API 测试。** 覆盖 404、409、空范围、跨课程知识点、重复请求与旧版本保留。

## 第三段：来源元数据

Codex 已把 T03 登记来源与 T08 异步提取的边界及请求样例写入契约。之后 javadeleon 增加 `sources` 表及临时库测试；萝卜头按定稿契约实现登记和读取接口。T03 验收只要求链接地址或笔记原文、课程归属、标题、类型、创建时间等内容可保存和读取；不宣称已抓取网页正文。

## 合并与验收

1. 先合并契约决定与 B 的迁移／仓储，再接 A 的服务／路由，最后做联调；任何字段变化先更新契约。
2. 全部测试使用临时库。运行既有持久化测试及新增数据库、API 测试；再在 `backend` 下执行 `python -m alembic upgrade head`，启动 API。
3. 手工走一遍：创建空课程、重名冲突、建父子知识点、修改自评、建两场考试、保存含“不考”条目的范围草稿、确认一次、修改后再确认、读取旧版本、重启后复查。
4. API 无 AI 密钥仍可完成上述操作；历史自评和旧正式范围不得丢失。测试结果和未完成项写入 T03 交接记录。
